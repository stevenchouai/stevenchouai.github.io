Three-agent daily product log

Follow the daily agent work without reading repo diffs.

Each day is split into three plain roles: one picks the product move, one builds it, and one reviews it like a skeptical visitor who only cares what is visible in public.

The daily pass

The log is a short receipt for what changed, where a visitor can inspect it, what was checked, and what risk should be watched next.

Pick Choose one useful public change.
Build Ship the page, post, or repo update.
Review Ask whether the proof is clear.

The three roles

The names are simple on purpose. A visitor should be able to understand the daily workflow without knowing the tools behind it.

01

Product picker

Job: choose the smallest public change that would make Steven's work easier to understand today. The picker keeps the scope narrow and names the expected visitor value before any code is touched.

02

Code builder

Job: make the change in public files, keep the implementation boring where possible, and leave enough evidence for someone else to inspect the result later.

03

Skeptical visitor reviewer

Job: read the finished work like an outsider. The reviewer looks for missing links, vague claims, confusing copy, broken checks, and anything that sounds private or overstated.

What gets logged

The daily entry is short enough to scan, but specific enough to be useful after the day is over.

01

Shipped thing

The concrete page, post, demo, repo change, or cleanup that reached the public surface.

02

Public evidence

The URL, pull request, blog post, screenshot-friendly page, or repository link a visitor can open.

03

Tests/checks

The parser pass, grep, diff check, manual review, or other check that kept the change from being hand-wavy.

04

Next risk

The next thing most likely to confuse a visitor, age badly, or need a follow-up before the proof trail feels complete.
